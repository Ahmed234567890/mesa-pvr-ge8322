# Mesa PowerVR GE8322 bring-up

Unofficial, experimental research toward a Mesa PowerVR (`pvr`) driver for the
PowerVR Rogue GE8322.

This repository contains research notes and tooling only. It does **not**
contain a working GE8322 driver or a Mesa source tree.

## Target hardware

| Item | Value |
|---|---|
| Device | Samsung Galaxy A03 Core `SM-A032F` |
| SoC | Unisoc SC9863A |
| GPU | PowerVR Rogue GE8322 |
| GPU BVNC | `22.86.104.218` |
| Vendor DDK | `1.18@6267915` (`sharkl3_android`) |
| Kernel | Linux `4.14.199`, aarch64 |
| Android | 14 / SDK 34 |
| Userspace | 32-bit ARM only (`armeabi-v7a`) |
| Kernel GPU driver | Proprietary `pvrsrvkm` |
| Kernel UAPI | `PVR_SRVKM_CMD` / `PVR_SRVKM_INIT` |
| Firmware | `rgx.fw.22.86.104.218`, `rgx.sh.22.86.104.218` |

## Current status

Validated on the host:

- Mesa `27.0.0-devel` builds with `-Dvulkan-drivers=imagination`.
- The `drm-shim` build enumerates supported BVNCs.
- `PVR_SHIM_DEVICE_BVNC=36.53.104.796` produces a working simulated
  `BXS-4-64` device in `vulkaninfo`.
- `PVR_SHIM_DEVICE_BVNC=22.86.104.218` fails with
  `pvr_device_info_init: Unsupported Device`, as expected.

Decoded from the vendor `pvrsrvkm.ko`:

- The vendor DDK has a GE8322 BNC entry for `22.104.218`.
- Feature mask: `0xc5844b3025`.
- The mask is identical to Mesa's GE8300 `22.102.54.38` entry.
- GE8322-specific values include FBCDC 3, FBCDC algorithm 3, 7 ISP IPP pipes,
  1 cluster, 1 raster pipe, 512-bit SLC cache lines, and 64 KB SLC.
- Errata mask: `0x8e408` (bits 3, 10, 13, 14, 15, 19).

See [`ge8322/vendor-features.md`](ge8322/vendor-features.md) for the full table.

## The hard blocker (partial progress)

Mesa `pvr` expects the mainline `drm/imagination` UAPI. The phone exposes the
proprietary `pvrsrvkm` UAPI instead. Adding a GE8322 device-info entry to Mesa is
not enough: the driver still cannot submit work to this kernel.

### Partial progress: Mesa ICD initialization works

The locally modified Mesa pvr ICD enumerates the PowerVR Rogue GE8322, passes
`vkCreateDevice`, and creates the dummy HWRT dataset through RGXTA3D func 16.
The ICD reports API version 1.2.363 and conformance version 1.4.3.3; that
reported value is **not** evidence of a conformance test. The Mesa ICD is not
yet a working renderer:

- **Queue submission**: Mesa `pvr-smoke` reaches `vkQueueSubmit`, then its
  RGXTQ func 3 bridge ioctl fails with `EINVAL` (`errno=22`). The current
  command is 68 bytes in / 12 bytes out; the DDK 1.18 32-bit-user/64-bit-kernel
  pointer layout still needs to be reconstructed and validated.
- **Presentation**: with Termux:X11 `:1` verified reachable, Mesa `vkcube`
  creates the device and dummy HWRT dataset but fails swapchain setup: bridge
  ioctl ID 11 / func 2 returns `EINVAL`, after which `vkcube` aborts. The
  verified Termux:X11 cube and `vkmark` results are from the separate vendor-HAL
  bridge, not Mesa.
- **Rendering/readback**: no successful Mesa queue submission or rendered
  output has been verified yet. The vendor clear-only capture is not a Mesa
  rendering test.
- **Usclib NIR blob** — target-ABI `pco_clc` generation needs automation in the
  cross-build.

The remaining work is therefore split into:

1. **Kernel/firmware path** — determine whether mainline `drm/imagination` can
   be backported and whether the vendor firmware is compatible.
2. **Mesa userspace** — add GE8322 device info and any compiler/command-stream
   fixes required by the hardware.
3. **OpenGL** — Mesa `pvr` is Vulkan-only; Kali OpenGL would need Zink on top,
   but Zink rejects the vendor ICD for lacking the mandatory
   `VK_EXT_robustness2.nullDescriptor` feature, and Mesa `pvr` cannot
   initialise against `pvrsrvkm`. Desktop GL 2.1 is instead provided by GL4ES
   on vendor GLES. See [opengl/zink-gate.md](opengl/zink-gate.md) for the
   evidence and the conditions to re-open that gate.

See [TESTING.md](TESTING.md) for the test matrix and ordered next steps.

## Mesa contribution policy

Mesa's PowerVR team explicitly declines LLM-generated contributions to
`src/imagination`. See:

- [Mesa PowerVR contribution policy](https://gitlab.freedesktop.org/mesa/mesa/-/blob/main/src/imagination/README.md#contribution-policy)
- [Mesa AGENTS.md](https://gitlab.freedesktop.org/mesa/mesa/-/blob/main/AGENTS.md)

Any Mesa driver changes must be authored and submitted by a human contributor in
accordance with that policy.
